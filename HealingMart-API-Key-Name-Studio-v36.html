API 키는 정리하고,
이름은 의미 있게.

TXT에서 API 키를 읽고, KEY_NAME은 공식·통용 기관 약칭을 최우선으로 사용하고, 기능명은 짧은 영어 의미어로 바꿉니다. API_KEY까지 포함해 최대 5토큰으로 압축하며, 로마자 표기는 약칭이나 번역어를 찾지 못했을 때만 마지막 fallback으로 사용합니다. 파일과 인증키는 서버로 전송하지 않고 현재 브라우저 안에서만 처리합니다.

새 API 이름만 먼저 등록해도 됩니다. 인증키는 선택이며, KEY_NAME을 비우면 의미 기반으로 자동 생성합니다.
서버 업로드 없음브라우저 로컬 처리인증키 입력은 선택이름·KEY_NAME 검색
예: 한국토지주택공사 청약정보는 LH_SUBSCRIPTION_API_KEY처럼 기관 약칭을 사용합니다. 외교부_국가∙지역별 여행경보는 MOFA_TRAVEL_ALERT_API_KEY, 조정 항목은 MOFA_ALERT_UPDATE_API_KEY처럼 짧게 구분합니다. 자동 이름이 이미 존재해도 KEY_2, KEY_3처럼 숫자를 먼저 붙이지 않습니다. 이름만으로 구분하기 어려운 경우에는 목록에서 KEY_NAME을 직접 수정할 수 있습니다. 실제 인증키까지 저장하는 JSON 백업은 민감정보가 포함되므로 개인 보관용으로만 사용하세요.
TXT 파일을 넣으면 대표 이름별로 자동 그룹화됩니다.
