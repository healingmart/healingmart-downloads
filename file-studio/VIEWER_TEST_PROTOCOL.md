# HealingMart Universal Viewer 검증 기준 — 2026-11-01

> 대상: File Studio 독립 테스트 브랜치와 별도 Cloudflare Worker. 실제 운영 tools.healing-mart.com은 변경하지 않음.

## 1. 지원 주장 원칙

- 확장자 목록만 있다고 지원으로 계산하지 않는다.
- 파서/로더가 존재해도 파일 내용 렌더링에 성공하기 전에는 **미검증**이다.
- 합격 기준을 세 단계로 분리한다:
  1. **샘플 통과**: 지정된 대표 파일로 실제 렌더링 + UI 동작 확인.
  2. **형식 검증 완료**: 다수의 독립 소스 파일, 참조 뷰어와 내용 대조, 손상·대형 파일, 복합 리소스, 브라우저 교차 테스트 통과.
  3. **미검증/미지원**: 공개 지원 형식에 포함하지 않음.
- 현재 샘플 통과는 **3D 확장자 8종 / 9개 정상 파일 시나리오**, 형식 전체 검증 완료는 **0종**. '수백 종 지원'은 근거 없음.

## 2. 테스트 데이터 원칙

- 지원 대상 확장자당 처음에 정상 샘플 최소 3개(간단한 파일, 실무용 파일, 여러 리소스·버전의 복잡한 파일), 오류 샘플 최소 2개(손상, 잘못된 확장자/외부 파일 누락)부터 구축한다.
- 200개 형식이면 최소 **1000개 샘플**을 준비하고, 형식별 필요에 따라 늘린다.
- 테스트 파일의 출처·권리·원본 프로그램·파일 크기·SHA-256·필수 연동 파일·기대 결과를 기록한다.
- 저작권 또는 재배포 허가가 없는 파일은 테스트에 활용하더라도 공개 샘플 저장소에는 배포하지 않는다.

## 3. 통과 요건(모든 단계 필수)

| 단계 | 검증 방법 |
|---|---|
| A 파일 감지 | 확장자와 파일 헤더·컨테이너 구조 대조, 잘못된 확장자 거부 |
| B 파싱 | 구조 파싱 성공·필수 종속 파일 연결, 타임아웃과 메모리 제한 |
| C 의미 있는 표시 | 3D 실제 메시·재질, 2D 실제 픽셀, 문서 페이지·텍스트, 오디오·영상 프레임 및 재생 등 |
| D 정합성 | Blender / 검증된 형식별 프로그램 / 원본 내보내기 결과와 좌표·페이지·색·텍스처 등 비교 |
| E 조작 | 3D 회전·확대·격자·캡처, 문서 페이지 이동·확대·검색, 영상 탐색 등 |
| F 예외 입력 | 손상·암호화·빈 파일·경로 누락·지원하지 않는 코덱에 정확한 오류 |
| G 운영 조건 | Chrome·Edge 외 Firefox, 실제 iOS/Android 및 저사양 기기 확인 |
| H 회귀 | 코드 업데이트 후 과거에 통과한 파일 전부 다시 테스트 |

## 4. 단순 화면 표시만으로는 불합격

- 3D: canvas 존재만 확인하지 않고 실제 메시 정점/삼각형 수, 유한 바운딩 박스, 텍스처 해상도 및 내용, 카메라·스냅샷을 검사.
- PDF/문서: 실제 페이지 수와 텍스트·폰트/도형 누락 여부를 참조 결과에 대조.
- 영상/음성: 실제 디코딩·탐색·재생, 길이·채널·프레임 정보 검증.
- 압축파일: 단순 목록뿐 아니라 파일 내부 선택 보기, CRC 검사, 경로 순회 취약점 방지 등.
- 미리보기 품질 또는 기능이 불완전하면 **부분 지원**으로 명시.

## 5. 증빙 파일

각 케이스의 JSON 결과, 스크린샷, 테스트 파일명·SHA-256, 브라우저 버전, 실행 일자·코드 커밋을 누적한다. GitHub Actions 자동 배포는 사용하지 않고 **독립 테스트 실행기**로 회귀 시험 후 결과만 기록한다. Cloudflare test Worker는 운영 페이지와 분리.

## 6. 현재 상태

- 8개의 3D 확장자: 대표적인 정상 파일 시나리오 통과(Chrome 및 Edge, 동일 Chromium 엔진).
- 9개 시나리오: GLTF 내장·외부 BIN을 따로 검증.
- 실제 Android/iOS·Firefox·다양한 제조사 FBX/DAE/3MF 및 250MB 이상은 미검증.
- 소스와 현재 검증 범위의 정형 상태는 `VIEWER_SUPPORT_AUDIT.json`에 기록.
